MDTEST · GETTING STARTED

Analyze MD data

A step-by-step guide to opening the MDTest Workbench for the first time. Automated dependency installation and environment set-up is provided. More advanced users may want to create their own environment separately.

Start in three steps

1
Extract the whole downloaded ZIP

On Windows choose Extract All… and open the resulting MDTest folder. Do not run files from inside the ZIP viewer.

2
Open the START file for your computer
Windows

Double-click
START_MDTEST_WINDOWS.bat

macOS

Open Terminal, then run
sh START_MDTEST_MAC.command

Mac security / installation guide

Linux

Run in Terminal
bash START_MDTEST_LINUX.sh

On Windows the launcher installs MDTest and JupyterLab into %LOCALAPPDATA%\MDTest\e, a short private user folder, to avoid Windows long-path errors. On macOS/Linux it uses the local .venv folder. Later launches normally skip installation.

3
Use JupyterLab in your browser

Open MDTestWorkbench.ipynb if necessary, choose Run → Run All Cells, and use the integrated Workbench. Keep the launcher window open while working.

Before first run: Install Python 3.11+ (Mac: 3.12/3.13 recommended) and make sure you have internet access for the one-time package downloads. Python is not bundled with MDTest. Windows installer users should select Add Python to PATH if offered.

Your first analysis

1
In Choose data, enter the supplied file examples/data/synthetic_variance_relaxation_independent.csv, click Load columns, then select observable 1.
2
Choose Auto Compare and click Run analysis. Inspect the separate MDTest and ESS/IACT start estimates and the diagnostic plots.
3
Click Export for a reproducible report. Diagnostic warnings require scientific interpretation; they do not necessarily indicate a software failure.

For exact manuscript benchmark values, use the full-scale settings in the User Manual. Default GUI settings need not reproduce them exactly.

Two notebooks, two purposes

For everyday analysis, use the Workbench. The second notebook is an optional tutorial for users who want to learn Python.

Mac user troubleshooting

If macOS blocks the launcher, the script lacks execute permission, or an existing Anaconda Jupyter uses a different Python kernel, see the Mac troubleshooting FAQ. This covers the real Mac installation issues reported by a scientific collaborator, with corrected commands.

Need help?

“No module named mdtest”

Close the old notebook and open it using the START launcher. You do not need to link src or configure PYTHONPATH.

Python not found?

Install an appropriate Python from python.org (Mac: 3.12/3.13 recommended), then double-click START again.

Windows long-path error installing JupyterLab?

The updated Windows launcher automatically installs into a shorter private location. See installation help; Windows system settings do not need to be changed.

Browser doesn't open?

Keep the launcher window open, copy its http://localhost:... link into a browser, and use it there.

Want to see a completed report without installing anything?

Open the included sample report. It is a static output, not the live application.

Moved the folder? Windows START keeps the private Python installation in a short user-owned folder, independent of Downloads or Documents. It updates the MDTest source link when the project folder moves. Your data and saved reports are unaffected.

Choose a data file in the Workbench

Local file: select an example CSV or a file uploaded through JupyterLab's left file browser; press Refresh list after adding a file. Choose file: select a file on your computer. A successful transfer displays File received and automatically loads the available columns. If no confirmation appears, use JupyterLab's file browser and Local file instead. File path: type a path and select Load columns.
