MDTest getting started

Starting MDTest on a Mac

macOS protects your computer from unverified downloaded programs. The MDTest shell launcher is not Apple-signed or notarized. It may be blocked when double-clicked. This is expected for a research script, but always use files from a source you trust.

1 · Install a compatible Python

For this version, choose Python 3.13 or 3.12 from python.org. Python 3.15 is recognized by START, although complete MDTest/Jupyter testing on it is pending. You can keep multiple Python versions installed side by side.

2 · Launch without opening an unverified program in Finder

  1. Extract the whole MDTest ZIP using Finder.
  2. Open Terminal (Applications → Utilities → Terminal).
  3. Type cd including the trailing space, then drag the extracted MDTest folder from Finder into Terminal and press Return.
  4. Type sh START_MDTEST_MAC.command and press Return.
  5. On first use it installs MDTest and JupyterLab privately; then open the local browser URL shown in Terminal, if the browser does not open automatically.
This runs a shell script you have chosen to trust; it does not turn off Gatekeeper for other programs or remove quarantine protections globally.

3 · If Finder shows “Apple could not verify…”

For a trusted downloaded copy, Apple documents a per-file exception under System Settings → Privacy & Security → Open Anyway after the blocked attempt. Do not disable your Mac’s security settings globally. Alternatively, use the Terminal steps above rather than double-clicking.

4 · Installation succeeds, but the notebook check fails?

The improved MDTest launcher now prints the Python version, each failing dependency import, and the actual MDTest package location. Send that diagnostic output to the developer to identify the precise problem. The launcher selects Python 3.13/3.12 first where installed; it can also use 3.14/3.15. When changing interpreter versions, the private environment is refreshed and the previous one preserved until setup succeeds.

Sending MDTest to a colleague

Send a link to the release file on GitHub rather than emailing the ZIP itself. Gmail blocks ZIP attachments containing Windows .bat launchers. Renaming the ZIP does not solve that policy.

Mac troubleshooting FAQ

A tested M4 Mac exposed three common setup traps: unsigned-file security warnings, missing script execute permissions, and confusion between Anaconda's old notebook kernel and MDTest's private Python. Do not use chmod 644 to add executable permission.
