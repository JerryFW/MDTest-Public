Mac troubleshooting FAQ

Security warnings, executable permissions, Python versions, Anaconda and Jupyter kernels

Start here: Extract the trusted MDTest ZIP. For the supported workflow, open Terminal in the extracted folder and run sh START_MDTEST_MAC.command. Python 3.13 or 3.12 is recommended for this software release.

These answers incorporate a real first-run experience on an Apple Silicon M4 Mac, with corrections to two commands that should not be copied uncritically.

Why does macOS say Apple cannot verify MDTest?

The launcher is unsigned/not notarized, so Gatekeeper cannot verify it. This is not proof of malware or of safety. Use a trusted project download. The simplest route is to open Terminal in the extracted MDTest folder and run the script explicitly.

sh START_MDTEST_MAC.command
If you prefer Finder, after a blocked attempt Apple documents System Settings → Privacy & Security → Open Anyway for a file you have independently decided to trust. Do not disable Gatekeeper globally or routinely strip quarantine metadata.

Why do I get Permission denied? Is chmod 644 correct?

No. chmod 644 removes execute permission. The initial field note had a typographical/permission mistake. Running through sh does not require an executable bit. For direct execution, grant it explicitly:

chmod +x START_MDTEST_MAC.command
./START_MDTEST_MAC.command
The package sets executable metadata, but some extraction tools drop it.

My Mac has Anaconda with Python 3.7. Must I uninstall it?

No. Keep Anaconda if you use it for other research. Python 3.7 is below MDTest’s requirement. Install a separate Python 3.13 or 3.12 from python.org; the MDTest launcher uses its own .venv and leaves Anaconda untouched.

You do not need Python 3.15 for MDTest. The Mac launcher recognizes 3.15 but prefers 3.13/3.12 where installed; full MDTest/Jupyter testing on 3.15 remains pending.

MDTest installed but the notebook says No module named mdtest

You may be using an Anaconda notebook kernel rather than the private MDTest Python. Close the existing notebook, launch through sh START_MDTEST_MAC.command, and use that Jupyter session. To inspect the current kernel, run:

import sys, mdtest
print(sys.executable)
print(mdtest.__file__)
The Python path should be under .venv, and the MDTest import should resolve to this project’s src/mdtest.

Can I use my old Anaconda Jupyter instead of the Easy-Start Jupyter?

Yes, optionally. First complete a normal MDTest setup. Then register the MDTest private Python as a kernel, rather than registering an unrelated Python 3.15 interpreter:

sh START_MDTEST_MAC.command --setup-only
./.venv/bin/python -m pip install ipykernel
./.venv/bin/python -m ipykernel install --user --name mdtest-private --display-name "MDTest (private Python)"
In your existing Jupyter interface choose Kernel → Change Kernel → MDTest (private Python). Avoid bare pip install notebook, which may target the wrong interpreter. This advanced route is not needed for normal use.

The final notebook check fails. What do I send?

Use the latest launcher. It now displays a Detailed notebook check with Python version, per-package import success/failure, and MDTest’s imported location. Copy that section and any traceback. For a non-installing diagnostic run:

sh START_MDTEST_MAC.command --check
A failed notebook check does not establish a statistical-engine problem.

Does an M4 Apple Silicon Mac need special steps?

The reported machine used an M4 processor. Use a compatible Apple Silicon Python installer and let MDTest’s private environment install matching dependencies.

Avoid mixing native ARM and Intel/Rosetta environments without explicitly managing them.
